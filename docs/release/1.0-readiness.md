## Decisions Needed

1. **Cron intervals.** Config validation accepts standard cron lines such as `*/5 * * * *` (`cron.ParseStandard` in `pkg/config/validate.go`), but the satellite scheduler parses only `@every`. On hot reload the old interval stays and an error is logged (`TestIntervalChangeToANonEveryScheduleReportsTheError`). On the next start `NewSchedulerWithInterval` fails inside `Satellite.Run` and the satellite does not start. A config with such a line can reach a whole fleet through Ground Control. Options: reject non-`@every` lines in validation, or teach the scheduler cron.
2. **Heartbeats above `SYNC_MAX_BODY_BYTES` (4 MiB).** Nothing on the satellite bounds the heartbeat: journal records carry unbounded error strings, and the BYO cached-image inventory is unbounded. The satellite has no handling for `413`, and its rejection counter moves only on a journal ack error, so a heartbeat over the cap would be refused on every beat with the same batch and the satellite would go stale. Found by code review, not reproduced. ADR-0015 does not cover it.
3. **Renewing journaled heartbeat budget.** 6 statements against 5: count the session lookup outside the budget, or combine the lookup and the renewal (a change to plan item 4). Dropping the transaction is ruled out by ADR-0015.
4. **Reserved names.** The generated router registers `GET /api/satellites/active` and `/stale` before `/api/satellites/{satellite}`, and `DELETE /api/groups/satellite` before `/api/groups/{group}` (`server.gen.go`). `fleet.ValidName` reserves none of these, so a satellite named `active` or `stale` cannot be fetched and a group named `satellite` cannot be deleted through the API. Verified by reading the registration order; there is no runtime test.

## Remaining Gaps

Known, not fixed, from the fix-round reports and this gate:

- containerd 1.x: `configureContainerd` always writes `plugins."io.containerd.cri.v1.images".registry.config_path`, the containerd 2.x key. A version 2 `config.toml` (containerd 1.x, many k3s installs) uses `io.containerd.grpc.v1.cri`. Not tested against a real containerd.
- `ExtractSatelliteNameFromSPIFFEID` falls back to the last path segment, so `/satellite/region/eu/x` and `/satellite/region/us/x` map to the same satellite name.
- `harborhealth` builds `HARBOR_URL + "/api/v2.0/health"`, so a trailing slash requests `//api/v2.0/health`; not checked against a real Harbor.
- `METRICS_ADDR` defaults to `:9464` on all interfaces without auth; the Helm chart Service does not expose it and adds no ServiceMonitor.
- `ListOutboxEvents` falls back to 100 for a limit out of range, while the spec documents 400; the CLI checks the limit itself.
- The OpenAPI spec does not list the `413` that `/login`, `/satellites/ztr`, `/satellites/spiffe-ztr` and `/oidc/*` answer above 64 KiB.
- After a `413` from `MaxBytesReader`, `statusRecorder` hides `requestTooLarge`, so the server may read up to 256 KiB more before closing the connection.
- `TestEmbeddedSpireCanceledStartupStopsProcess` falls back to cancelling after 10s if the fake script never writes its trap marker; no failure reproduced.
- `TestWorkerIsHiddenAndNeedsNoClient` (`internal/groundcontrol/cli`) takes 60s.
- Webhook delivery polls the outbox behind the xmin guard; the logical decoding reader of ADR-0019 is not implemented, and there is no delivery-lag metric.
- Website (branch `website-cr26`, 5e5a9737): Hugo build and internal link check clean; source links 404 until 1.0 reaches `main`.
