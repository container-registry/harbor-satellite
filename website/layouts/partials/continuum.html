The Registry Continuum

One Fleet from Data Center to Isolated Site

Every site is a satellite in the same fleet, with the same groups, configs and policy. How content reaches it, from Harbor or from a peer, is a property of the site, not a separate product.

  1. Harbor Core

    Central Harbor + Ground Control

    Define groups, configs and policies once. Harbor holds the artifacts, Ground Control the fleet.

    Source of truth

  2. Big Edge

    Regional DC, factory floor, telco PoP

    Satellite on Kubernetes or as a systemd service, continuous replication and SPIFFE/SPIRE identity.

    Live sync

  3. Small Edge

    Retail store, vehicle, single-board device

    Single binary with an OCI image layout on local disk. The runtime pulls through the loopback proxy, or images go straight into k3s with direct delivery.

    Live sync, offline tolerant

  4. Isolated

    Restricted networks, ships, OT zones

    Same satellite record, same groups, same policy. Satellites copy from peers on the isolated network.

    Peer copy, last known state

Disconnected sites

Same Process When the Link Drops

A satellite that loses its uplink keeps its replicated content on local disk and keeps serving it. On an isolated network, satellites that share groups copy artifacts from each other's registries before they try Harbor. When Harbor's state list cannot be fetched, a satellite replicates its last known list from peers, and a brand-new satellite can start from a bootstrap desired-state file.

The site stays a satellite in the same fleet. There is no second inventory to keep in sync.
