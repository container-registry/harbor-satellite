Why Harbor Satellite

Built for Sites You Cannot Babysit

Extend Harbor to every edge location with reliability, security and central management. All features →

Reliability

Artifacts are prepositioned in a crash-safe OCI layout at each site. When Harbor or Ground Control is unreachable, existing content stays and replication resumes when the link returns.

Security

Register with a one-time token or a SPIFFE X.509 SVID over mTLS. Each satellite gets its own Harbor robot account, scoped to its groups, optionally rotated before expiry, and revocable.

Fleet Management

Group artifacts, assign groups and configs to satellites, and see each one as pending, online, stale or revoked, with whether it has converged.

Isolated Networks

Satellites copy artifacts from each other's registries before they try Harbor, replicate their last known state from peers while Harbor is unreachable, and can start from a bootstrap desired-state file.

Local Pull Endpoint

A pull-only OCI proxy on 127.0.0.1:8585 serves the local store. The satellite points containerd, CRI-O, Podman or Docker at it, with the upstream registry as fallback.

Lightweight

One satellite binary with an ORAS-backed OCI image layout, or replication into a registry you already run at the site. Images for amd64, arm64, ppc64le, s390x and riscv64.
